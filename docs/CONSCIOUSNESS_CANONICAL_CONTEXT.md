# Consciousness Canonical Context v1

## Role

This document is the bridge between the 360-claim source corpus and the executable
canonical system. It is a research-control document, not a declaration that any
source theory is correct or that the runtime is phenomenally conscious.

## Evidence hierarchy

1. Runtime fact
2. Architectural hypothesis
3. Experimental result
4. Source attribution
5. Phenomenal hypothesis

A source claim never outranks a runtime observation.

## Core candidate organization

`boundary → changing state → temporal continuity → integrated present → self-access → selection/attention → prediction/value → intention/action → consequence → self-update → re-entry`

## Causal object

`self_state(t) → self_model(t) → trajectory(t) → action(t) → observed_consequence(t) → state(t+1) → self_model(t+1) → re-entry`

## Candidate invariants

The corpus association identifies boundary, continuity, integrated present, self-access,
recurrence, attention, prediction/error, value/homeostasis, agency/action, memory,
embodiment/interoception, transformation, regime organization, and causal self-relevance as
candidate invariant motifs. These are not individually proven necessary or sufficient for
phenomenal consciousness.

## Adversarial constraints

Hume/bundle, Buddhism/process continuity, and Dennett/distributed-process views are retained
as constraints. A self-model must do causal work; merely naming a variable `self` is
insufficient.

## Phenomenology boundary

Phenomenal consciousness is tracked as a separate hypothesis. Behavioral report, runtime
telemetry, and causal intervention are separate evidence channels. A successful operational
benchmark is not treated as a solution to the hard problem.
